# Lines makiba holds

Status: checked by `tests/role_settings.rs` (Issue M4-3): every reference in the last column names a role settings entry, a hook, a test or an Issue that exists.

These are the lines of paddock's predecessor inventory (section 6.2), the things that must not happen, with what holds each in makiba. "Kept" lines (L-K) were held in claude-org-ja and paddock and are carried; "New" lines (L-N) exist because the base that runs the terminals is not a sandbox or a permission broker. A rule in a role's rules file (`roles/<role>/rules.md`) says the same to the agent, but a rule alone does not count as a holder: each line is held by a setting, a hook or a test, or names the Issue that will hold it (`Open`).

How to read a reference:

- `roles/<role>/settings.json: <text>`: that role's settings hold a string equal to the text or ending with it (a permission rule, a sandbox path, a hook's command); `roles/<role>/settings.json: /a/b` is a setting at that JSON pointer.
- `hook <name>`: `makiba hook <name>`, a hook of the binary.
- `tests/<file>` or `tests/<file>::<fn>`: a test file, or a test function in it.
- `Open: #<n>`: not held yet; the Issue that will hold it.

The Bash hooks read the command as text, as claude-org-ja's do: a spelling they do not read passes. Every refusal by a makiba hook names the hook, the line below it holds and the part of the command that matched (Issue 306): `makiba: refused by hook <name> (line <id> in docs/design/lines.md): <reason>. Matched: "<text>"`, `tests/hook_refusal_names.rs`. Issue 140 decided, per line, what holds it without reading the command (a fact of the launch or of the sandbox); where that holder exists it is named first and the hook is the second layer, and where it is only decided the line names its Issue. Two facts of Claude Code bear on these lines: for a linked worktree its sandbox also opens the clone's shared `.git` for write (its refs and objects; not `config` or `hooks/`), which is why a code run is not a linked worktree since Issue 241, and a host outside the network allow-list is judged per command in auto mode, not refused, unless `sandbox.network.strictAllowlist` is on.

## Deny rules that refuse without a reason

Claude Code refuses a call that a `permissions.deny` rule of a role's settings matches with only "Permission to use ... has been denied": the rule is not named (Issue 306). A role's `PreToolUse` hooks run before those rules, so a rule refuses silently only what the hooks let through. Each rule of the worker's, the secretary's and the curator's settings is listed here with why it stays; `tests/hook_refusal_names.rs` checks that the list and the settings agree.

- `Bash(git commit *--no-veri*)`, `Bash(git commit -n*)`, `Bash(git commit * -n*)`: the no-verify hook refuses git's flag that skips the hooks first, in the spellings it reads, naming itself and L-K3; these rules also hold an abbreviation of the long flag that the hook does not read. They stay silent for now: they match the whole command text, so a commit message holding the flag's letters is refused too, with no reason. Reading git's arguments instead of the text, so that the hook alone holds the flag and these rules can go, is Issue 300, still open.
- `Bash(git push:*)`: the push hook refuses every git push it reads first, naming itself and L-K2. The rule matches the start of a command as Claude Code splits it, not text inside a message, so it is silent only on a spelling the hook does not read, where it is a second layer.
- `Bash(hc:*)`, `Bash(herdr-core:*)`, `Bash(herdr-app:*)`: the same, after the base hook, which refuses the base's commands naming itself and L-N2.
- `Bash(gh pr:*)`, `Bash(gh issue:*)`, `Bash(gh release:*)`, `Bash(gh workflow:*)`, `Bash(gh api:*)` (worker, curator): the push hook refuses each gh call that writes first, naming itself and L-K2. These rules also refuse a reading call (gh issue view) with no reason. That call cannot work for these roles anyway: they hold no GitHub login and GitHub's hosts are outside their strict network list (L-K2), so the rule only makes the failure immediate. A worker reads an Issue through the secretary.
- `Read(~/.config/herdr-core/**)`, `Edit(~/.config/herdr-core/**)`, `Read(~/.config/herdr-app/**)`, `Edit(~/.config/herdr-app/**)`, `Read(~/.local/state/herdr-core/**)`, `Edit(~/.local/state/herdr-core/**)`, `Read(~/.config/makiba/base/**)`, `Edit(~/.config/makiba/base/**)`, `Read(~/.config/makiba/person.key)`, `Edit(~/.config/makiba/person.key)`, `Read(~/.config/makiba/gate.key)`, `Edit(~/.config/makiba/gate.key)`, `Read(~/.config/gh/hosts.yml)`, `Edit(~/.local/share/makiba/**)`, `Edit(~/.claude/settings.json)`: a path rule of the file tools matches the path the tool is given, never text inside a command, and Claude Code's refusal names that path, which is what matched. Each guards a secret, the base or makiba's installed code (L-K1, L-K5, L-N1, L-N9).
- `Edit(.claude/settings*.json)`, `Edit(.mcp.json)`: the same; for the worker and the curator the boundary hook refuses these edits first, naming itself and L-K5.
