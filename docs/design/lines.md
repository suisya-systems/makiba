# Lines makiba holds

Status: checked by `tests/role_settings.rs` (Issue M4-3): every reference in the last column names a role settings entry, a hook, a test or an Issue that exists.

These are the lines of paddock's predecessor inventory (section 6.2), the things that must not happen, with what holds each in makiba. "Kept" lines (L-K) were held in claude-org-ja and paddock and are carried; "New" lines (L-N) exist because the base that runs the terminals is not a sandbox or a permission broker. A rule in a role's rules file (`roles/<role>/rules.md`) says the same to the agent, but a rule alone does not count as a holder: each line is held by a setting, a hook or a test, or names the Issue that will hold it (`Open`).

How to read a reference:

- `roles/<role>/settings.json: <text>`: that role's settings hold a string equal to the text or ending with it (a permission rule, a sandbox path, a hook's command); `roles/<role>/settings.json: /a/b` is a setting at that JSON pointer.
- `hook <name>`: `makiba hook <name>`, a hook of the binary.
- `tests/<file>` or `tests/<file>::<fn>`: a test file, or a test function in it.
- `Open: #<n>`: not held yet; the Issue that will hold it.

The Bash hooks read the command as text, as claude-org-ja's do: a spelling they do not read passes. A line they hold is still held by them, with that limit noted; Issue 140 is for holding these lines without reading the command as text.
