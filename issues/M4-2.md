# M4-2 The sandbox reaches the door and nothing of the base

## Why

A deny rule matches command text; a script or a direct socket connection is outside it. paddock wrote the sandbox entries for herdr-core but could not measure them, because its deny rule always refused first.

## What to build

- Per-task settings (from M3-2) deny the base's socket and state folders and the person key file for read and write, and deny `state.db` for read and write (an agent's `status` goes through the door; the local reader is the person's). They name no Unix socket path as allowed: agents reach `makibad` by the MCP configuration in the launch arguments (M3-4).
- `scripts/probes/door-and-base-reach.sh`: probe P1 as a script a person can rerun, for the steps the first run did not reach (probes.md, P1), and probe P11 (the port and the token from a sandboxed Bash). They were run by hand before M2 and M3 with hand-written settings; this repeats them with the settings `makibad` really writes.
- The result recorded in `docs/design/probes.md` with versions and date.

## Carried from

- paddock: `scripts/probes/core-api-reach.sh`

## Definition of done

The first commit adds `tests/task_settings_shape.rs`, failing, with the trailer `Acceptance-Test: tests/task_settings_shape.rs`. At head `cargo test --test task_settings_shape` passes and asserts:

- The per-task settings written for a run contain the base's denies, the person key file's denies and the `state.db` denies, and name no Unix socket path as allowed.
- The settings name no path inside the worktree as writable configuration.
- The launch arguments written for a run carry the token and the environment does not (shape only; the host rerun of P11 is what shows that a sandboxed Bash cannot read it, and it is the proof of the goal clause that an agent's token cannot be read from its own Bash).
