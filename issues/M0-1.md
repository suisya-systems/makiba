# M0-1 Repository skeleton, CI and the acceptance job

## Why

Nothing can be merged test-first until the repository can run a test in CI and say whether a declared test failed at the test commit and passed at head.

## What to build

- `pyproject.toml` (package `makiba`, Python 3.11+, no runtime dependency), `makiba/__init__.py`, `tests/`.
- `.github/workflows/ci.yml`: jobs `tests` (pytest), `lint` (ruff), `acceptance`.
- `scripts/acceptance-check.sh <base> <head>`: paddock's checker, changed to run each declared path with `python3 -m pytest <path>` instead of `bash <path>`. Rules 1, 2 and 4 of paddock's `docs/design/acceptance-check.md` are kept as they are.
- `.github/acceptance-check` with the one line `acceptance`, so claude-org-ja's landing gate takes this job as the test-first evidence (claude-org-ja #1274).
- `README.md`: what makiba is, in five lines, and a link to `docs/design/plan.md`.

## Carried from

- paddock: `scripts/acceptance-check.sh`, `tests/acceptance-check.test.sh`, `.github/acceptance-check`, `docs/design/acceptance-check.md`

## Definition of done

The first commit adds `tests/test_acceptance_check.py`, failing, with the trailer `Acceptance-Test: tests/test_acceptance_check.py`. At head it passes and asserts:

- In a scratch git repository: a branch whose first commit declares a failing test and whose head makes it pass yields `ACCEPTANCE: pass`.
- A branch whose declared test already passes at the test commit yields `ACCEPTANCE: fail`.
- A branch with no trailer yields `ACCEPTANCE: none`.

## Notes

This pull request adds the checker after its own test commit, so its own `acceptance` job fails. It is merged in `human` mode. Branch protection (require `acceptance`, `tests`, `lint`; require branches up to date) is a setting only the owner can make.
