# M3-1 Take queued runs within capacity

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

The secretary asks; the dispatcher decides when there is room.

## What to build

- `makiba/daemon/dispatch.py`: each pass, take `queued` runs oldest first while the count of runs in `in_use` plus launches not yet `verified` or `failed` is below `max_concurrent_workers` (organization setting, default 4).
- A run taken gets its `run_launch` row moved from `planned` onward by M3-2 to M3-6.

## Definition of done

The first commit adds `tests/test_dispatch_capacity.py`, failing, with the trailer `Acceptance-Test: tests/test_dispatch_capacity.py`. At head it passes and asserts:

- With capacity 2 and three queued runs, two launches start and the third waits.
- When one finishes, the third starts on the next pass.
- Runs are taken in `dispatched_at` order.

- G4 Dispatch and close record what was observed
