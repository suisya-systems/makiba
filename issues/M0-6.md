# M0-6 The incident table and its check

## Why

G1 is only checkable if the incident table is data a test can read.

## What to build

- `docs/design/incidents.md` as delivered, kept as a Markdown table.
- `tools/check_incidents.py`: parses the table; fails when a row has an empty `Test` cell or names a file that does not exist. A row whose guarding Issue is still open may name a file that does not exist yet only if the file is listed in `docs/design/incidents-pending.txt`; that list must be empty by M7-1.

## Definition of done

The first commit adds `tests/test_check_incidents.py`, failing, with the trailer `Acceptance-Test: tests/test_check_incidents.py`. At head it passes and asserts:

- A table with a row lacking a test fails the check.
- A row naming a missing file fails unless the file is in the pending list.
- The delivered table passes.
