# M2-7 Deliver messages: the box, the wake line and typed delivery

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

A push that did not arrive, a recipient that was working, and an agent program with no channel all end in the same place: the message is still `pending`, and the recipient has to be told to read it.

## What to build

- `src/daemon/inbox.rs`: the function behind the door verb `inbox` (spec section 12): the caller's `pending` messages, each wrapped, oldest first, within the limit, marked `delivered`. The door lists the tool (M3-3); this Issue holds the logic.
- The wake line in `src/daemon/delivery.rs`: a `pending` row whose recipient is `idle` or `done`, with no push to it in the last 10 s, gets `WAKE_LINE` typed with `Base::send`, after the prompt line of the recipient's screen is read (nothing is typed that pass if anything is on it), at most once per recipient in 60 s. A recipient with no channel is unconfirmed from the start and goes by this route alone. This is a real route for any agent program, not a fallback left untested.
- The typed route, only on the sender's request: a function for `send` and `answer` with `typed` (M3-3 and M6-4 pass the argument through the door). It goes to a worker or the curator whose status is `idle` (`only_if_idle`) or `done` (status read just before); any other status is `conflict`, and nothing is stored or typed. `typed` to the secretary is a `usage` error. The row is `delivered` when `Base::send` returns, and `makibad` never retries it.

## Definition of done

The first commit adds `tests/inbox_wake.rs`, failing, with the trailer `Acceptance-Test: tests/inbox_wake.rs`. At head `cargo test --test inbox_wake` passes and asserts:

- A push after which no turn starts: the wake line is typed once into the `idle` recipient, and the row is `delivered` when the recipient's `inbox` returns it.
- A message pushed while the recipient was `working`: when the recipient turns `done` the wake line is typed, and `inbox` returns the message with the same id it was pushed with.
- A recipient with no channel gets the wake line and the box only.
- The wake line is not typed while the prompt line shows typed input, and not twice in 60 s (a clock the test controls).
- `send` with `typed` to a worker that is `idle` types the wrapped text once and the row is `delivered`; to a `working` worker it is `conflict` and nothing is stored or typed; to the secretary it is `usage`.
- `inbox` for one agent never returns another agent's message.
