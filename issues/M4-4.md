# M4-4 makiba up: start the base cleanly

## Why

Whatever starts the base hands its environment to every terminal. Started from inside an agent, that turned transcripts off in paddock.

## What to build

- `makiba up`: refuses when run inside an agent (any of the `CLAUDE*` session variables, or one of the base's own terminal variables, is set), with a message saying to use a login shell.
- Calls `Base::start()`: the `makiba` session's core with `notes = false`, so that the base sends no notices and gives agents no rules of its own (requirement R2). Never stops or restarts a base it did not start.
- Creates the person key file if it is absent (M3-3's function), and refuses nothing about an existing one.
- Runs `claude --version` and refuses to start the secretary or any worker outside the supported range of M0-2, naming both. Claude Code can update itself between checks; a launch after such an update is caught at the next `up`, not at the launch.
- Starts `makibad` (`makiba daemon`, detached). Starts the secretary unless `--no-secretary` (the secretary itself is M6-2).

## Carried from

- paddock: `skills/org-start/scripts/org-start.sh` `--check` (as the list of preconditions)

## Definition of done

The first commit adds `tests/up.rs`, failing, with the trailer `Acceptance-Test: tests/up.rs`. At head `cargo test --test up` passes and asserts:

- With `CLAUDE_CODE_SESSION_ID` set, `makiba up` exits non-zero and starts nothing.
- After `up`, a launched test agent's environment has none of the caller's extra variables named in spec section 6.4.
- A second `up` starts nothing new and exits 0.
- After `up` the person key file exists with mode 0600 in a folder of mode 0700, and a second `up` leaves its content unchanged.
- With a stand-in `claude` on the path that prints a version outside the range, `up` exits non-zero and starts neither secretary nor worker.
