# M0-2 Pin the base's version and install it the same way everywhere

## Why

herdr-core releases every few days and calls its API a preview. makiba must run against one known version and refuse any other.

## What to build

- `makiba/base/version.py`: the supported range (`>=0.1.21,<0.1.22`) and a check of the version `Base.hello()` returns.
- `scripts/install-base.sh`: installs the pinned release into a given prefix; used by CI and by a person.
- `docs/upgrading-the-base.md`: the steps to move the pin (run M1-5's test against the new definition, rerun the probes).

## Definition of done

The first commit adds `tests/test_base_version.py`, failing, with the trailer `Acceptance-Test: tests/test_base_version.py`. At head it passes and asserts:

- A version inside the range is accepted.
- A version outside it raises before any other call is made, with a message naming both versions.

## Goal clause

- G6 The base is a part that can be replaced, and an update of it does not break makiba
