# M0-2 Pin the base's version and install it the same way everywhere

## Why

herdr-core releases every few days and calls its API a preview. makiba must run against one known version and refuse any other. The pin is not meant to follow the releases: moving it costs a test run and several probes, so it moves on purpose and rarely.

## What to build

- `makiba/base/version.py`: the supported range (`>=0.1.21,<0.1.22`, one patch release; the version the design was read against and the probes of `docs/design/probes.md` are run on) and a check of the version `Base.hello()` returns.
- `scripts/install-base.sh`: installs the pinned release into a given prefix; used by CI and by a person.
- `docs/upgrading-the-base.md`: when the pin moves, and what a move costs. It moves when a release carries something makiba needs, when the pinned release can no longer be installed, or at the owner's monthly look at the base's changelog; not on every release, and not more than about once a month. A move reruns: M1-5's test against the new release's own definition; the whole suite on the stand-in and on the real base; probes P1, P3, P4 and P5 on the new version (they measure how the base is reached, typed into and launched, which a patch release has changed before: 0.1.20 changed sends), each a few hours of the owner's time; P2 reruns itself in CI. A probe may be skipped only when the changelog shows nothing touching its area and the record says so. P6 is not rerun.
- The range stays one patch release. A wider range would let a version in that no probe has run on. It is revisited only after three pin moves in a row needed nothing but the number changed.

## Definition of done

The first commit adds `tests/test_base_version.py`, failing, with the trailer `Acceptance-Test: tests/test_base_version.py`. At head it passes and asserts:

- A version inside the range is accepted.
- A version outside it raises before any other call is made, with a message naming both versions.
- `docs/upgrading-the-base.md` names M1-5's test file and each of P1, P3, P4 and P5.

## Goal clause

- G6 The base is a part that can be replaced, and an update of it does not break makiba
