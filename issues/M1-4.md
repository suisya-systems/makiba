# M1-4 Errors as types

## Why

The dispatcher decides differently for 'not found', 'blocked' and 'try again'. It should not parse messages to tell them apart.

## What to build

- Map the base's errors to the variants of `BaseError`: `NotFound`, `Blocked`, `StatusMismatch`, `Finished`, `Unavailable`, and `Other` for the rest, each carrying the base's own kind, message and hint. herdr-core answers `{error: {kind, message, hint}}`.

## Definition of done

The first commit adds `tests/base_errors.rs`, failing, with the trailer `Acceptance-Test: tests/base_errors.rs`. At head `cargo test --test base_errors` passes and asserts:

- `send` to a blocked terminal returns `BaseError::Blocked`.
- `send` with `only_if_idle` to a working terminal returns `BaseError::StatusMismatch`.
- An unknown terminal returns `BaseError::NotFound`.
