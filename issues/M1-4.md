# M1-4 Errors as types

## Why

The dispatcher decides differently for 'not found', 'blocked' and 'try again'. It should not parse messages to tell them apart.

## What to build

- Map the base's errors to `NotFound`, `Blocked`, `StatusMismatch`, `Finished`, `Unavailable`, and `BaseError` for the rest, each carrying the base's own kind, message and hint. herdr-core answers `{error: {kind, message, hint}}`.

## Definition of done

The first commit adds `tests/test_base_errors.py`, failing, with the trailer `Acceptance-Test: tests/test_base_errors.py`. At head it passes and asserts:

- `send` to a blocked terminal raises `Blocked`.
- `send` with `only_if='idle'` to a working terminal raises `StatusMismatch`.
- An unknown terminal raises `NotFound`.
