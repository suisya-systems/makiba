# M6-8 Relay a permission prompt

## Why

A resident organization cannot call a person to a terminal for every prompt. paddock's relay (read again, press one key only if unchanged) passed on a host.

## What to build

- On `blocked` with kind `permission`: `makibad` reads the screen, asks the agent module to recognize the prompt, and adds a `pending` entry of kind `prompt` with `prompt_text` and `prompt_sum`; `prompt_seen`.
- `makiba answer <id> yes|no` for a prompt: read the screen again; if the terminal is still `blocked` and the sum matches, press the one key (the one-time yes, or escape) and write `prompt_answered`; otherwise reject `stale` and press nothing.
- When the terminal leaves `blocked` on its own, the entry is withdrawn.

## Carried from

- paddock: `skills/org-escalation` (`prompt`, `answer`), `scripts/probes/worker-prompt-relay.sh`, inventory row L-N3

## Definition of done

The first commit adds `tests/prompt_relay.rs`, failing, with the trailer `Acceptance-Test: tests/prompt_relay.rs`. At head `cargo test --test prompt_relay` passes and asserts:

- A scripted prompt answered `yes` receives exactly one key and the agent continues.
- If the prompt text changes between record and answer, the answer is `stale` and no key is sent.
- A prompt the module does not recognize becomes a pending question with the screen text, and no key is ever sent for it.
