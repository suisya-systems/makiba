# M0-4 The test agent

## Why

Every test through M3 needs an agent that behaves on command: reports status, takes input, shows the dialogs a real agent shows.

## What to build

- `src/agents/fake.rs` (the `Agent` for the test agent) and `tests/common/fake_agent.rs`, the program it launches, built as the binary `makiba-fake-agent` by a `[[bin]]` entry in `Cargo.toml`. Tests find it through `CARGO_BIN_EXE_makiba-fake-agent`; a release ships only `makiba`.
- The program follows a script given on its command line: emit OSC 7501 records (`idle`, `working`, `blocked` with a kind, `done`, `error`), wait for a line of input, print a startup dialog with a cursor line, print a permission prompt, exit with a code, or hang.
- It records every line and key it receives to a file the test reads.

## Carried from

- herdr-core: `fake_tui.py` in its own tests (as a reference)

## Definition of done

The first commit adds `tests/fake_agent.rs`, failing, with the trailer `Acceptance-Test: tests/fake_agent.rs`. At head `cargo test --test fake_agent` passes and asserts:

- A script of `working, blocked(permission), done` is seen in that order through `Base::get`.
- Keys sent to a scripted dialog arrive in the record file in order.
