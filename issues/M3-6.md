# M3-6 A launch is verified only by an observed first turn

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

On 2026-08-18 two workers were reported as dispatched that had never started (I-1).

## What to build

- `worker_spawn_verified`, `run_launch.stage = verified` and `runs.status = in_use` are written in one transaction, and only when a `working` status or a turn event for that terminal has been recorded after launch.
- No verification within the timeout (default 180 s): `worker_spawn_failed`, stage `failed`, the terminal is left for inspection, and the secretary gets a notice.
- `conversation_id` is read from the agent module once verified.

## Definition of done

The first commit adds `tests/test_spawn_verified.py`, failing, with the trailer `Acceptance-Test: tests/test_spawn_verified.py`. At head it passes and asserts:

- An agent that reaches `working` is verified and its run is `in_use`.
- An agent that launches and never reports is `failed` after the timeout; the run is not `in_use`; a notice to the secretary is queued.
- There is no code path that writes `worker_spawn_verified` without a status or turn event id in its payload.
