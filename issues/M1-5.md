# M1-5 Compatibility test against the base's own definition

## Why

The pin (M0-2) says which version; this says which parts of it makiba depends on, so that moving the pin is a test run and not a read-through.

## What to build

- `src/base/uses.rs`: the operations, parameters and result fields the implementation uses, as data.
- A test that checks every entry against what the base says about itself: herdr-core's OpenRPC schema (`hc schema`, or the vendored copy for the stand-in run).

## Definition of done

The first commit adds `tests/base_compat.rs`, failing, with the trailer `Acceptance-Test: tests/base_compat.rs`. At head `cargo test --test base_compat` passes and asserts:

- Green on the pinned version.
- With one used field removed from a copy of the definition, the test names that field.

## Goal clause

- G6 The base is a part that can be replaced, and an update of it does not break makiba

Depends on M1-1
