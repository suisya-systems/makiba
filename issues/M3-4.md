# M3-4 Launch

## Why

The launch is where the environment is decided. paddock measured that the base's own variables (`HC_*`) and the starter's `CLAUDE*` variables reach a worker unless they are removed.

## What to build

- `makiba/daemon/launch.py`: build `argv` from the agent module and call `Base.launch` with name, tags (`makiba.role`, `makiba.task_id`, `makiba.spawn`, `makiba.org`), `env` (`MAKIBA_KEY`, `MAKIBA_DOOR`, `MAKIBA_AGENT_ID`), the unset list of spec section 6.4, and `cwd`.
- Write `worker_spawned` and `run_launch.stage = launched`. The key's hash goes into `agents`.

## Definition of done

The first commit adds `tests/test_launch.py`, failing, with the trailer `Acceptance-Test: tests/test_launch.py`. At head it passes and asserts:

- `Base.get` right after launch shows the four tags.
- The test agent's recorded environment contains `MAKIBA_KEY` and none of the names in spec section 6.4, even when the test's own environment sets them.
- The key in the environment hashes to the stored `key_sha256`.
