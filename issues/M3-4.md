# M3-4 Launch

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

The launch is where the environment is decided. paddock measured that the base's own variables (`HC_*`) and the starter's `CLAUDE*` variables reach a worker unless they are removed.

## What to build

- `src/daemon/launch.rs`: build `argv` from the agent module and call `Base::launch` with name, tags (`makiba.role`, `makiba.task_id`, `makiba.spawn`, `makiba.org`), `env` (no key), the unset list of spec section 6.4, and `cwd`. The agent module's `argv` carries the MCP configuration with the door's address and the agent's token (spec section 4).
- Write `worker_spawned` and `run_launch.stage = launched`. The key's hash goes into `agents`.

## Definition of done

The first commit adds `tests/launch.rs`, failing, with the trailer `Acceptance-Test: tests/launch.rs`. At head `cargo test --test launch` passes and asserts:

- `Base::get` right after launch shows the four tags.
- The test agent's recorded environment contains no key and none of the names in spec section 6.4, even when the test's own environment sets them; its recorded argument list carries the token.
- The token in the argument list hashes to the stored `key_sha256`.
