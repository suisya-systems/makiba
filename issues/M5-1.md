# M5-1 Close is refused before the done report

## Why

In claude-org-ja a hook stopped the dispatcher from closing a pane before its retrospective. The line that matters is narrower: no close before the worker's own report has been recorded.

## What to build

- The `close` verb: `conflict` unless the run has a `report_done`, or `--abandon` is given (which records who abandoned and sets the run `abandoned`).
- A `close` for a run that is already closed is `done` again, not an error.

## Definition of done

The first commit adds `tests/test_close_gate.py`, failing, with the trailer `Acceptance-Test: tests/test_close_gate.py`. At head it passes and asserts:

- `close` before any report is rejected with `conflict` and nothing is ended.
- `close` after `report done` is accepted.
- `close --abandon` before a report is accepted and the run becomes `abandoned`.
