# M2-2 Record status and terminal events

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

Everything the organization knows about a worker's state comes from what the worker reported, written down as it happened.

## What to build

- `src/daemon/monitor.rs`: for each event of a terminal carrying `makiba.org`, write `terminal_status`, `terminal_turn` or `terminal_gone` (spec section 10), tied to the run by the `makiba.task_id` tag.
- A status record identical to the last one written for that terminal is not written again.

## Definition of done

The first commit adds `tests/monitor.rs`, failing, with the trailer `Acceptance-Test: tests/monitor.rs`. At head `cargo test --test monitor` passes and asserts:

- A scripted run `working, blocked(question), working, done` produces exactly those four status events in order.
- A terminal without the organization's tag produces none.
- A terminal that exits produces one `terminal_gone` with its exit code.
