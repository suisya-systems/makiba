# M3-7 A launch survives the dispatcher dying at any step

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

A dispatcher that can be restarted safely is the point of making it code.

## What to build

- On start, for every `run_launch` not `verified` or `failed`: at `planned`/`worktree_ready`/`settings_ready`, continue from that stage; at `launched`/`dialog_passed`, look for a terminal with `makiba.spawn=<spawn_id>` and adopt it, or mark the launch `failed` if none exists.
- A test helper that kills `makibad` at a named step.

## Definition of done

The first commit adds `tests/test_launch_idempotent.py`, failing, with the trailer `Acceptance-Test: tests/test_launch_idempotent.py`. At head it passes and asserts:

- For each stage boundary: kill there, restart, and assert exactly one terminal carries the spawn tag and the run ends `in_use`.
- Kill after `Base.launch` returned but before the stage was written: the terminal is adopted, not launched again.
