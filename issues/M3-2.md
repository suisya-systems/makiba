# M3-2 Prepare the worktree and the per-task settings

## Before starting

Do not start until probes P1 to P5 and P7 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version.

## Why

A worker in a fresh git worktree stopped at the trust dialog in paddock, because trust comes from the repository, not from a parent folder (I-9). And a worker must not be able to edit its own rules.

## What to build

- Kind `code`: `git worktree add` from the project's own repository into `$MAKIBA_WORKERS_DIR/<project>/<task_id>`, on a new branch from the project's default branch (or `--branch`).
- Kind `document`: create `$MAKIBA_DOCS_DIR/<task_id>/` with an empty `out/`.
- The per-task settings file at `<state>/settings/<task_id>.json`, written by the agent module (`write_task_settings`): sandbox on, write surface = the worktree and a temp dir, the door allowed.
- Nothing is written inside the worktree.
- `run_launch.stage`: `worktree_ready`, then `settings_ready`.

## Definition of done

The first commit adds `tests/test_worktree.py`, failing, with the trailer `Acceptance-Test: tests/test_worktree.py`. At head it passes and asserts:

- After preparation `git status` in the worktree is clean and `git worktree list` in the project shows it.
- No file exists in the worktree that is not in the project's tree at that commit.
- Running preparation twice for the same launch changes nothing the second time.
- A `document` launch creates the working folder with `out/` and touches no git repository.
