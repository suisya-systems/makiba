# M2-3 Anomaly rules

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version.

## Why

The model dispatcher looked at screens every three minutes and judged. These are the same judgments as functions, so they can be tested and they run every time.

## What to build

- `makiba/daemon/anomalies.py`: the nine rules of spec section 11 as pure functions of (run, latest status, events, now); for the secretary, which has no run, of its terminal record instead.
- `anomaly_raised` once per (run, rule); `anomaly_cleared` when it stops being true; then it may raise again.
- Each raised anomaly queues one `notice` message to the secretary (delivery is M2-4).

## Definition of done

The first commit adds `tests/test_anomalies.py`, failing, with the trailer `Acceptance-Test: tests/test_anomalies.py`. At head it passes and asserts:

- Each rule: a scene that raises it, and the same scene one second earlier that does not.
- A scene held for ten passes raises once.
- `done_no_report` does not raise when a `report_done` exists after the last turn.
- `secretary_gone`: a `terminal_gone` for the terminal named `secretary` with no renewal under way raises it once, as does a secretary with no status 180 s after launch; a gone caused by `makiba renew` does not.
