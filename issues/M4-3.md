# M4-3 Carry the role settings and the git guard hooks

## Why

The lines paddock lists as 'kept' (L-K1 to L-K12) are held by settings and hooks that already exist and have tests.

## What to build

- `roles/worker/`, `roles/secretary/`, `roles/curator/`: settings and rules files from paddock, with the mailbox commands replaced by tool calls of the door and the two wrapper sentences of spec section 8 added.
- Hooks from claude-org-ja, ported as subcommands `makiba hook <name>` with the cases of their tests: push refused for workers, dangerous git, `--no-verify`, recursive delete of worker folders, the worker boundary, foreground subagents. The shell versions need `jq`, and the worker-boundary hook falls back to `python3`; makiba's hooks need nothing but the binary.
- Workers start in auto permission mode.
- `docs/design/lines.md`: paddock's table of lines (inventory section 6.2) with, for each, what holds it in makiba.

## Carried from

- paddock: `templates/worker-rules.md`, `worker-settings.json`, `secretary-rules.md`, `secretary-settings.json`, `curator.md`; `docs/design/predecessor-inventory.md` section 6.2
- claude-org-ja: `.hooks/block-git-push.sh`, `block-dangerous-git.sh`, `block-no-verify.sh`, `block-workers-delete.sh`, `check-worker-boundary.sh`, `block-foreground-subagent.sh`, `.hooks/lib/`, `tests/test-block-git-push.sh`, `test-block-dangerous-git.sh`, `test-check-worker-boundary.sh`, `test-hooks-payload-fail-closed.sh`

## Definition of done

The first commit adds `tests/role_settings.rs`, failing, with the trailer `Acceptance-Test: tests/role_settings.rs`. At head `cargo test --test role_settings` passes and asserts:

- The cases of the carried hook tests, ported, pass.
- Every line in `docs/design/lines.md` names a settings entry, a hook or a test that exists.
- The rules file of each role (secretary, worker, curator) contains the two wrapper sentences of spec section 8, exactly as `src/spec.rs` holds them.
