# M2-4 Deliver messages: the push and its confirmation

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

Three incidents were about a message that did not arrive or arrived by a route nobody read (I-3, I-5, I-7). makiba has one default route, and a ledger that shows what is still unconfirmed. This Issue is the push and its confirmation; the box and the wake line are M2-7, and the channel server is M2-8.

## What to build

- `src/daemon/delivery.rs`: each pass, for every `pending` delivery not yet pushed (`attempt` is 0) whose recipient has a channel (the agent module's `has_channel()` and a connected channel server), push the wrapped text of spec section 8 through the channel, whatever the recipient's status. `attempt` goes up and `last_attempt_at` is set. Nothing is typed for this. Delivery runs inside `makibad` and stops only when the process dies, which the heartbeat shows. The channel is a seam (a function the agent module supplies), so this Issue is tested without the channel server.
- Confirmation (spec section 8): a push to a recipient that was `idle` or `done` is confirmed, and the row becomes `delivered`, when its status shows a turn start within 10 s (a first proposal). In every other case the row stays `pending` for M2-7.
- The wrapper of spec section 8 and its limits: bodies over the limit are cut with the `show` line.

## Definition of done

The first commit adds `tests/delivery.rs`, failing, with the trailer `Acceptance-Test: tests/delivery.rs`. At head `cargo test --test delivery` passes and asserts:

- A message to an `idle` agent that has a channel is pushed once, nothing is typed, and the row becomes `delivered` when the test agent starts a turn within the window.
- A push after which no turn starts leaves the row `pending`, and it is not pushed a second time.
- A message pushed while the recipient is `working` stays `pending`.
- A recipient with no channel (the test agent launched without one) is never pushed to; its row stays `pending` with `attempt` 0.
- Killing `makibad` between a push and the ledger write, then restarting, does not lose the message: it may be pushed again with the same id, and the test asserts at-least-once.
- Every pushed text begins with `<makiba ` whatever the body is, and a body containing `</makiba>` cannot close the wrapper.
- A body over the limit is cut and carries the `show` line.
