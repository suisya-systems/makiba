# M2-4 Deliver messages

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

Three incidents were about a message that did not arrive or arrived by a route nobody read (I-3, I-5, I-7). makiba has one default route, and a ledger that shows what is still unconfirmed.

## What to build

- `makiba/daemon/delivery.py`: each pass, for every `pending` delivery not yet pushed (`attempt` is 0) whose recipient has a channel (the agent module's `has_channel()` and a connected channel server), push the wrapped text of spec section 8 through the channel, whatever the recipient's status. `attempt` goes up and `last_attempt_at` is set. Nothing is typed for this. Delivery runs inside `makibad` and stops only when the process dies, which the heartbeat shows.
- `makiba/channel_server.py`: the per-session channel server that Claude Code starts from the MCP configuration. It declares the channel capability, takes the wrapped texts for its agent from `makibad` with the agent's token, and emits one `notifications/claude/channel` for each. How it receives them from `makibad` (a poll or a held request) is decided here.
- Confirmation (spec section 8): a push to a recipient that was `idle` or `done` is confirmed, and the row becomes `delivered`, when its status shows a turn start within 10 s (a first proposal). In every other case the row stays `pending`.
- The wake line: a `pending` row whose recipient is `idle` or `done`, with no push to it in the last 10 s, gets `WAKE_LINE` typed with `Base.send`, after the prompt line of the recipient's screen is read (nothing is typed that pass if anything is on it), at most once per recipient in 60 s. A recipient with no channel is unconfirmed from the start and goes by this route alone.
- The door verb `inbox`: returns the caller's `pending` messages, each wrapped, oldest first, within the limit, and marks them `delivered`.
- The typed route, only on the sender's request: `send` and `answer` take `typed`. It goes to a worker or the curator whose status is `idle` (`only_if='idle'`) or `done` (status read just before); any other status is `conflict`, and nothing is stored or typed. `typed` to the secretary is a `usage` error. The row is `delivered` when `Base.send` returns, and `makibad` never retries it.
- Bodies over the limit are cut with the `show` line.

## Definition of done

The first commit adds `tests/test_delivery.py`, failing, with the trailer `Acceptance-Test: tests/test_delivery.py`. At head it passes and asserts:

- A message to an `idle` agent that has a channel is pushed once, nothing is typed, and the row becomes `delivered` when the test agent starts a turn within the window.
- A push after which no turn starts leaves the row `pending`; the wake line is typed once into the `idle` recipient, and the row is `delivered` when the recipient's `inbox` call returns it.
- A message pushed while the recipient is `working` stays `pending`; when the recipient turns `done` the wake line is typed, and `inbox` returns the message with the same id it was pushed with.
- A recipient with no channel (the test agent launched without one) gets the wake line and the box only.
- The wake line is not typed while the prompt line shows typed input, and not twice in 60 s (a clock the test controls).
- Killing `makibad` between a push and the ledger write, then restarting, does not lose the message: it may be pushed again with the same id, the test asserts at-least-once, and the row ends `delivered`.
- `send` with `typed` to a worker that is `idle` types the wrapped text once and the row is `delivered`; to a `working` worker it is `conflict` and nothing is stored or typed; to the secretary it is `usage`.
- Every pushed or typed text begins with `<makiba ` whatever the body is, and a body containing `</makiba>` cannot close the wrapper.
- A body over the limit is cut and carries the `show` line.
