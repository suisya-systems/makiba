# M2-8 The channel server

## Before starting

Do not start until probes P1 to P5 and P7 to P11 are recorded as run, with versions and date, in `docs/design/probes.md` (Results). They are run by hand before any Issue of M2 or M3, on the pinned base version. A probe run in part names the steps not run; those are run before the Issue that relies on them lands.

## Why

A Claude Code channel is carried by a small server that Claude Code starts for each session. It is another process to start and to give a credential, as claude-org-ja's sidecar is.

## What to build

- `src/channel.rs`, run as `makiba channel`: the per-session channel server that Claude Code starts from the MCP configuration (spec section 4). It is the same binary as `makibad`, so the two are always one version. It speaks MCP on its standard input and output (JSON-RPC, serde_json), declares the channel capability, takes the wrapped texts for its agent from `makibad` with the agent's token, and emits one `notifications/claude/channel` for each. How it receives them from `makibad` (a poll or a held request) is decided here; over the agents' port, the request is written on std's `TcpStream` and its answer read with httparse, with no HTTP client crate (plan.md section 5.1).
- `makibad` knows whether an agent's channel server is connected (M2-4's `has_channel` and connection check). When the server stops, the messages stay `pending`.

## Definition of done

The first commit adds `tests/channel_server.rs`, failing, with the trailer `Acceptance-Test: tests/channel_server.rs`. At head `cargo test --test channel_server` passes and asserts:

- With a stand-in for the `makibad` side, one stored message produces exactly one notification whose text equals the wrapped text.
- A server given a wrong token receives nothing.
- After the stand-in `makibad` restarts, the server reconnects and receives messages again.
- While the server is stopped, `makibad` reports the agent as not connected and the messages stay `pending`.

## Notes

Tested here against a stand-in for `makibad`; with the real door it runs from M3-3, and with real Claude Code in M4-5. Not yet shown (probes.md, P11): that the environment and arguments of this process are out of a sandboxed Bash's reach.
